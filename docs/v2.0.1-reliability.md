# 방출 2.0.1 · 저장 안정성

2026-11-08 검수에서 재현한 네 가지 실패 경로를 수정했습니다. 기존 문 이미지·타이포그래피·작업 공간과 비공개 정책을 유지합니다.

## 1. 여러 탭에서 작업한 원고 보호

공유된 계정 캐시 하나를 모든 탭이 덮어쓰던 구조를 탭별 UUID 키로 변경했습니다. 각 탭은 자신의 미전송 백업만 갱신하고, 서버 저장 확인 후 자신의 임시 키만 제거합니다. 다른 탭의 미전송 원고는 그대로 남습니다. 이전 버전의 계정 캐시는 삭제하지 않고 별도 사본으로 옮깁니다.

재접속하면 상단에 보호된 원고 수가 표시됩니다. 계정 메뉴에서 원고를 읽고 JSON을 내려받을 수 있습니다. 글 복구는 서버 최신 프로젝트를 먼저 읽은 뒤 현재 원고를 복구 전 백업으로 남기고 선택한 본문을 복원합니다. 작품 설명·메모·과거 기록을 오래된 프로젝트 전체로 덮어쓰지 않습니다. 그림·음악 백업은 메타데이터 JSON을 제공하며 바이너리 원본이 포함되지 않습니다. 저장 공간 부족이나 사이트 데이터 삭제까지 보호하는 서버 백업은 아닙니다.

## 2. 중단된 가져오기 이어서 진행

추가형 마이그레이션 0001이 import_sessions 테이블을 만듭니다. 프로젝트 준비와 가져오기 계획 저장을 동일한 D1 트랜잭션에 넣습니다. 시작 당시 원고·설명·메모·일일 기록·파일 해시·대표 버전 연결을 보관하며, 중간에 로컬 프로젝트를 수정해도 진행 중 계획은 바꾸지 않습니다. 계획 JSON도 전체 텍스트 저장 한도에 포함됩니다.

재시도는 이미 보관되고 실제 R2 객체가 존재하는 파일을 건너뜁니다. 남은 원본이 있는 브라우저에서 ‘프로젝트 가져오기 / 계속’을 선택합니다. 마지막에 서버가 파일 해시를 매핑해 현재 버전·날짜별 버전·방출 메타데이터를 연결하고 계획 완료를 같은 트랜잭션에 저장합니다. 완료 응답이 끊겨도 다시 시도할 수 있습니다. 진행 중에는 일반 프로젝트 편집을 막습니다. 이전 v2.0에서 생성된 미완료 복사도 원본과 정확히 일치하고 파일이 원본 계획의 부분집합일 때만 이어받습니다.

일일 20개 업로드 제한은 유지합니다. 제한에 걸리면 다음 UTC 날짜에 계속할 수 있습니다. 다른 기기에 원본 파일이 없는 경우 원래 브라우저에서 이어서 진행해야 합니다. 취소·프로젝트 삭제 기능은 이번 수정에 포함하지 않습니다.

## 3. 응답 유실에도 원본 유지

파일 ID와 용량 예약을 동일한 D1 트랜잭션에서 생성합니다. 실패 시 R2 객체를 삭제하는 보상 처리를 제거했습니다. 미완료 파일과 예약을 남기고 같은 원본 해시로 재시도하면 같은 ID·경로에서 이어갑니다. 조건부 R2 저장으로 동시 재시도가 기존 객체를 교체하지 못하게 합니다. 미리보기 크기가 달라지면 추가 용량만 원자적으로 예약합니다.

완료 상태라도 필요한 객체가 실제 존재하는지 확인한 뒤 성공을 반환합니다. 완료 직후 D1 응답이 끊기면 실제 상태를 다시 읽고 확인하며, 확인 자체도 실패하면 다음 재시도를 기다립니다. 이전 버그로 객체가 없어진 파일은 같은 원본을 다시 올려 복구할 수 있습니다. 미완료 예약도 한도에 포함하며 자동 정리는 제공하지 않습니다.

## 4. 이미지 검사

서버는 원본과 미리보기를 용량 예약·R2 저장 전에 검증합니다. PNG는 청크 길이·순서·CRC·색상 정보·종료와 압축된 스캔라인 길이/필터까지 확인합니다. JPEG는 프레임·세그먼트·스캔·종료 구조를, WebP는 RIFF 크기·청크 경계·VP8/VP8L 헤더·치수를 확인합니다. 4천만 화소 초과 원본과 1600px 초과 미리보기를 거부합니다. 클라이언트도 이미지 비트맵을 만들기 전에 검사합니다. 원본을 서버에서 재인코딩하지 않습니다.

JPEG/WebP 검사는 컨테이너와 구조 검사이며 모든 압축 픽셀을 완전히 디코딩하는 검사는 아닙니다. 브라우저는 미리보기 생성 시 실제 원본 디코딩도 수행합니다. Free 플랜에서 최대 크기 파일의 CPU 시간은 실제 운영 환경에서 별도 관측이 필요합니다. 유료 리소스는 활성화하지 않았습니다.

## 검증

63개 자동 테스트와 TypeScript 검사, 배포 빌드가 통과했습니다. 임시 로컬 D1/R2에서 탭 A 저장과 탭 B 충돌 후 새로고침·복구, 여러 파일 중 첫 파일 이후 중단·재개, D1 커밋 후 응답과 재조회 모두 유실, 동시 동일 파일 요청, 이미 완료된 파일의 객체 복구, 손상 이미지 거부를 검증했습니다. 운영 사용자의 기록에 시험 데이터를 쓰지 않았습니다. 두 개의 실제 물리 기기에서 로그인해 동기화하는 검증은 수행하지 않았습니다.
