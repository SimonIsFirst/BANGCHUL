# BANGCHUL v2.0 개발 보고

기준일: 2026-11-08 (한국 시간)

## A. 기존 시스템 진단

실제 저장소는 SimonIsFirst/BANGCHUL이며 기반은 codex/creative-workspace-v1-2의 d59b6ea입니다. main과 기존 두 PR은 병합하지 않았습니다. 변경 파일이 없는 상태에서 원격 최신 내용을 확인하고 codex/multimedia-platform-v2를 분리했습니다.

기존 React 19 / TypeScript 6 / Vite 8 앱은 공개된 정적 Sites 호스팅을 사용했습니다. 별도 정적 Wrangler 프리뷰 설정은 있었지만, Workers API·로그인·D1/R2·그림/음악 업로드는 없었습니다. 7장면 온보딩, D-Day, 설명·메모, 원고 자동 저장과 날짜별 읽기 전용 달력은 구현되어 있었고 기존 테스트 31개가 통과했습니다.

위험은 로컬 용량·삭제, 기기별 기록 분리, 여러 탭의 마지막 쓰기 우선, 매일 누적되는 긴 원고와 서버 소유권 검증 부재였습니다. 실제 사용자 기록을 읽거나 초기화하지 않고 가상 로컬 데이터로 검증했습니다.

## B. 구현과 데이터

### 사용자 경험

- 제목 화면 안에서 글·그림·음악 선택. 기존 7장면 흐름, 명조 헤드라인, B 배경과 연기 유지.
- 글: 기존 편집기를 재사용. 과거 원고 확인 후 복원, 직전 원고의 별도 보호 백업, 백업 재조회·복원. 이전 편집기의 이탈 저장이 복원 결과를 덮지 않도록 프로젝트 ID와 복원 세대를 검사.
- 그림: JPG/PNG 원본 그대로 보관. 최대 1600px/.86 WebP 미리보기와 400px/.8 썸네일을 브라우저에서 별도 생성. 확대, 수정본, 이전 버전 조회·현재 버전 선택. 버전 목록을 펼칠 때 썸네일 로드.
- 음악: MP3 원본 보관, 재인코딩 없음. HTML5 오디오 재생·일시정지·구간 이동, preload=metadata. 서버의 Range/HEAD/416 처리.
- 일반 UI에 [Pretendard 공식 동적 서브셋](https://github.com/orioncactus/pretendard#다이나믹-서브셋) 적용. 기존 문 이미지 SHA256 423A2AE86BDBD7F8AEA88180F1610602ECA9C87CC4EA0A77B8688BBB4FE0D066 유지.

### 보존·계정·이관

기존 bangchul:mvp:v1 키와 version: 1을 유지합니다. kind가 없는 프로젝트는 글입니다. 본문·설명·메모·시간대·일일 기록을 변경 없이 읽습니다. 새 필드는 선택적으로 확장합니다.

현재 원고 workspace, 날짜 대표 원고 history, 파일 버전 mediaVersions, 현재 파일 currentVersionId, 날짜 대표 파일 mediaHistory, 복원 전 원고 restorePoints를 분리합니다. ReleaseArtifact는 비공개 상태, 버전/마감/시간대와 꺼진 자동 공개 동의·판매 플래그를 표현하는 준비용 타입입니다. 공개·결제 실행 API는 없습니다.

현재 로그인은 호스팅이 제공하는 ChatGPT 로그인입니다. 구글·카카오 직접 로그인은 연결하지 않았으며 UI에도 명시합니다. 익명은 로컬 작업을 계속합니다. 계정 공간은 사용자가 열고, 비어 있는 계정에만 브라우저 프로젝트를 확인 후 복사합니다. 로컬 원본 키·파일은 삭제하지 않습니다. 파일은 서버에서 재계산한 SHA256·크기를 비교하고 전체 프로젝트를 다시 읽어 복사 결과를 검증합니다.

계정 저장은 사용자별 기기 백업 후 직렬화된 서버 쓰기로 처리합니다. 서버 확인 전에는 서버 저장 완료로 표시하지 않습니다. 네트워크 실패 시 입력과 기기 백업을 유지하고, revision 충돌 시 자동 덮어쓰기를 막습니다. 확인 후 기기 캐시를 별도 키에 복사·검증하고 서버 기록을 다시 여는 복구 경로가 있습니다. JSON 백업에는 바이너리가 없으므로 원본 파일은 따로 내려받습니다.

파일 키는 projects/{projectId}/versions/{uuid}/original.ext, preview.webp, thumbnail.webp입니다. 공개 URL 대신 키·MIME·해시·크기·버전 ID를 보관합니다. 로컬 파일은 IndexedDB, 계정 파일은 비공개 R2입니다.

### D1 / API

| 테이블 | 역할 |
| --- | --- |
| users | 사이트 내 사용자 ID |
| projects | 소유자·분야·설명/메모 메타데이터·revision |
| workspaces | 현재 글과 시각 |
| daily_history | 프로젝트+로컬 날짜의 유일 대표 원고 |
| restore_backups | 복원 전 원고 |
| file_versions | 원본·파생 파일 메타데이터, pending/ready |
| release_artifacts | 비활성 공개·소장 준비 메타데이터 |
| usage_limits | 원자적인 저장량·업로드·쓰기 횟수 한도 |

외래 키, 소유자 유일 인덱스, 프로젝트별 해시 유일 인덱스, 날짜·파일 인덱스를 설정했습니다. Drizzle 최초 SQL과 스냅샷을 생성하고 로컬 마이그레이션을 적용했습니다. 사용자 데이터 삭제·시드는 없으며 Neon/Hyperdrive는 도입하지 않았습니다.

| 경로 | 동작 |
| --- | --- |
| GET /api/session | 로그인·저장소 준비 상태 |
| GET /api/project | 본인 프로젝트를 트랜잭션으로 읽기 |
| PUT /api/project | 소유권/revision 검사 후 본문·기록 원자적 저장 |
| POST /api/projects/:id/files | 소유자만 검증·한도 확인 후 파일 보관 |
| GET/HEAD /api/files/:id/:variant | 소유권 검사 후 원본/미리보기/썸네일 전달 |

프로젝트 삭제·공개 API와 계정 초기화 버튼은 없습니다. 로컬 초기화는 기존 프로젝트 키만 지웁니다. IndexedDB 파일은 원본 보호를 위해 남기며 초기화 후 다시 연결하는 UI는 아직 없습니다. 초기화 전 중요한 원본을 내려받아야 합니다.

## C. 보안과 비용

Sites dispatch의 검증된 ID를 서버 인증에 사용하며 이메일은 표시용입니다. SQL은 매개변수 바인딩과 소유권 조건을 사용합니다. 익명 401, 타인 파일/프로젝트 404, 저장 충돌 409로 차단합니다. 변경 요청은 같은 origin을 검사합니다. JSON·업로드 스트림의 실제 바이트, MIME·확장자·파일 서명을 확인합니다. HTML/SVG는 허용하지 않습니다.

고유 버전 키로 원본과 수정본을 보존합니다. 실패한 업로드는 ready로 노출하지 않으며 신규 파일/용량 예약을 정리합니다. 정리에 실패하면 예약을 유지해 무제한 재시도를 막습니다. 중단 후 남은 pending 파일 정리 작업은 후속 과제입니다.

공개 R2 URL은 없고 파일/API는 private, no-store 및 Vary: Cookie를 사용합니다. 파일은 nosniff와 same-origin resource policy를 적용합니다. 이미지 원본은 attachment, 미리보기는 별도 WebP입니다. API 키·실제 비밀값을 소스/로그에 넣지 않았습니다. Sites 밖에서 IDENTITY_PROVIDER=sites를 사용하면 안 됩니다. 외부 Cloudflare 배포에는 독립 OAuth 검증이 필요하며 로컬 설정은 인증을 기본 차단합니다.

### 초기 운영 제한

| 항목 | 한도 |
| --- | --- |
| JPG/PNG | 원본 10MiB / 브라우저에서 4천만 화소 이하 |
| MP3 | 원본 20MiB |
| 서버 파생 이미지 | 미리보기 2MiB / 썸네일 .5MiB |
| 프로젝트 파일 | 50버전, 원본+파생 합계 100MiB |
| 서버 전체 파일 | 512MiB |
| 업로드 | 프로젝트 UTC 일 20회 / 전체 UTC 월 500회 |
| 계정 | 계정당 1프로젝트 / 전체 50프로젝트 |
| 원고·기록 | 프로젝트 8MiB / 전체 100MiB의 내용 예산 |
| 서버 변경 요청 | 사용자당 분 60회 / 전체 UTC 일 7,000회 |
| 이관 | 파일 20개, JSON 8MiB, 신규/변경 기록 약 240개 이내 |

서버 한도는 트랜잭션으로 검사하며 동시 요청 초과를 테스트했습니다. 기록 날짜는 창작자의 로컬 날짜, 비용 제한 기간은 UTC입니다. 초과 시 새 저장을 거절하고 이전 기록을 자동 삭제하지 않습니다.

### 공식 요금 확인

아래는 Cloudflare 일반 상품 기준입니다. 현재 Sites 관리형 호스팅의 청구 상태를 뜻하지 않습니다.

- Workers Free: 동적 요청 일 100,000회, 호출당 CPU 10ms. Paid는 월 최소 $5와 사용량 과금. [공식 요금](https://developers.cloudflare.com/workers/platform/pricing/)
- D1 Free: 일 읽기 5백만 행·쓰기 10만 행, 총 5GB. Free 초과는 쿼리/저장을 제한하고 Paid 초과는 사용량 과금. [공식 요금](https://developers.cloudflare.com/d1/platform/pricing/)
- R2 Standard 무료량: 월 10GB-month, A 100만/B 1천만 요청. 초과 저장 $0.015/GB-month, A $4.50/백만, B $0.36/백만. 인터넷 egress는 무료. Infrequent Access 조건은 다름. [공식 요금](https://developers.cloudflare.com/r2/pricing/)
- Images Free: 월 고유 변환 5,000개. Paid 포함량 초과 변환은 1,000개당 $0.50 등 별도 과금. 이번에는 브라우저 변환을 쓰고 유료 Images를 활성화하지 않음. [공식 요금](https://developers.cloudflare.com/images/pricing/)

개인 Cloudflare 계정의 플랜·청구 상태를 조회할 연결은 확인되지 않았습니다. 해당 계정에서 유료 리소스를 만들거나 요금제를 변경하지 않았습니다. 현재 Sites의 관리형 D1/R2 선언과 게시 경로를 사용합니다. 한도는 청구액을 보장하는 지출 상한이 아니며 요청/읽기 남용 및 계정 전체 비용은 별도 모니터링이 필요합니다. Free CPU에서 최대 파일·대규모 부하의 적합성은 측정하지 않았습니다.

## D. 실제 검증

- 기존 31개 + 신규 24개 = **55개 테스트**. TypeScript와 프로덕션 프론트엔드/Worker 빌드를 검증합니다. 계정/로컬 작업 공간 선택도 URL에 유지해 새로고침 후 같은 공간을 다시 엽니다.
- 실제 로컬 D1/R2: 구 데이터 복사·재조회, 익명/타인 차단, 동시 저장 409와 원자성, 원본 바이트 동일성, 중복 업로드, 실패 예약 복구, Range/HEAD/416, 용량 한도 동시성.
- 브라우저: 그림/음악 신규 온보딩, PNG/JPG 원본·두 수정본·과거 조회·확대, 새로고침 후 파일 복원. MP3 97.4초 디코딩, 실제 재생·일시정지, 새로고침 복원.
- 가상 구버전 글: 설명·메모·본문 보존, 과거 조회 시 현재 글 불변, 확인 후 복원, 복원 직전 글 별도 백업과 재조회, 새로고침 후 복원 결과 유지.
- 390px 및 320px에서 화면 가로 넘침 없음. 실제 모바일 키보드·저사양 기기는 미검증.
- npm audit 전체 0건. Vite/Wrangler 수정 버전과 개발 도구 esbuild override 적용. Drizzle 재생성 변경 없음 확인.
- QA 코드와 가상 원고·공개 MDN 음원은 저장소 및 배포 아카이브 밖에 있습니다. 사용자 작품/운영 계정 기록을 초기화하지 않았습니다.

운영에서 배포 성공, D1의 8개 테이블, 계정 저장소 준비 상태, 익명 및 위조 헤더의 작품 접근 401, 실제 로그인된 계정의 작업 공간 조회를 확인했습니다. 기존 브라우저 기록은 수정 없이 유지했습니다. 미실행: 실제 다른 물리 기기에서 로그인·저장, OS 저장 권한 철회·전원 차단, 최대 파일/데이터 부하, 모든 색상·투명 이미지 회귀. 자동 공개·판매·댓글은 의도적으로 미구현입니다.

## E. 파일과 후속 과제

수정: App, OnboardingScene, ProjectDashboard, WorkspaceEditor, CalendarHistory, local-repository, 프로젝트 도메인, 폰트·빌드 설정.

추가: AccountControls, MediaWorkspace, media-store, cloud-repository, media/restore 도메인, worker의 index/database/files/security/quota, db/schema, SQL/스냅샷, Worker 빌드·로컬 Wrangler, 새 테스트.

기존 공개 Site ID/주소를 유지하고 정적 앱을 Worker 앱으로 전환합니다. 개인 Cloudflare 배포나 새 도메인 연결은 실행하지 않습니다. 별도 브랜치/PR로 v1.2 위 변경만 검토할 수 있습니다.

후속: 구글·카카오 직접 로그인, 다중 프로젝트·계정 삭제/보관, JSON 가져오기와 보호 캐시 목록, 부분 이관 재개, pending 파일 정리·사용량 대시보드, 동일 브라우저 여러 탭의 기기 백업 충돌 보완, 원본 정밀 디코딩 검사, 실제 Free 부하 측정. 자동 공개·판매는 별도 동의·예약 실행·권한·정산 단계로 진행합니다.
